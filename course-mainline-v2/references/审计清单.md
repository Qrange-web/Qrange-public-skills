# 课程主线审计清单

> 产出课程主线后、跑 Wiki 联动之前，必须过一遍这份审计。4 个维度：可靠性 / 信息完整性 / 框架忠实度 / 格式。

## 1. 可靠性（引用与事实是否可信）

- 第 7 节每条「原文纠正」是否逐字引用源材料？还是把 AI 概括塞进引号冒充原文？
- 第 8 节每条观点：转述是否忠实？有没有把作者/讲者没说的话安到作者/讲者头上？类型标注（核心主张 / 方法论框架 / 经验主张 / 趋势判断 / 引用观点 / 金句修辞）是否合理？
- 有没有把「推测」写成「事实」、把「作者立场」写成「客观规律」？
- 事实陈述（作者名、书目年份、概念定义、讲者背景）是否与源材料一致？

**红线**：引号内必须是逐字原文；概括必须移出引号并标注「编者概括」。

## 2. 信息完整性（是否遗漏源材料重要内容）

- 对照源材料目录/大纲，逐节检查覆盖。
- 重点：多条细则归纳成几组时，是否漏掉独立小节；示例型章节（如「不该问的问题」「好问题与蠢问题」）是否覆盖。
- 区分「可接受的压缩」与「重要信息丢失」。整节消失 = 丢失。

## 3. 框架忠实度（归纳结构是否忠于源材料）

- 提炼的框架是源材料内在结构，还是 AI 强加的外部结构？
- AI 自创框架是否用「编者说明 / 编者归纳」标注了？
- 同一条原文是否被映射到两个不同位置（重复映射，自相矛盾）？
- 归组是否把性质不同的规则硬塞进一组？

**允许提炼，但每条归纳必须能指出对应源材料章节/段落。**

## 4. 格式（硬约束，可用 checks.py 自动验证）

- 9 模块齐全、标题一字不差
- 粗体不包标点、标题层级不跳级、第 5 节三列表格
- 命名规范（按用户指定路径/文件名输出）、frontmatter 字段

## 执行方式

- 格式：跑 `references/checks.py`。
- 其余三维度：逐条对照源材料。复杂材料用 workflow 多 agent 并行 + 对抗验证；简单材料 inline 检查。
- 产出：列出「确认的问题 + 严重程度 + 修复建议」，区分必须改 / 该改 / 可选。**审计只出报告，不擅自改，修复前让用户确认。**
